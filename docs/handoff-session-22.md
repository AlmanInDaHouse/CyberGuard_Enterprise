## Forensic escalón 3 (evidence hash-chain) — delivery declaration

Forensic step 3 (evidence integrity / hash-chain) is **delivered in full** — the *"auditable"* promise (`blueprint.md:33`, `:527-535`) is now honest in code.

**The model (ADR-0016, Accepted):**

- **Evidence unit = the canonicalized SPEC-010 drill output**, not raw ClickHouse rows — the drill already produces a deterministic content set (`FINAL` at `queries.ts:259` + the TS `Set` dedup at `queries.ts:251`), decoupled from `ReplacingMergeTree` non-determinism.
- **Canonicalization = total order `(time, event_id)` + JCS (RFC 8785).** The total order required the **SPEC-010 amendment** (co-located in `dbadf4d`); the `queries.ts:262` edit landed in A+B.
- **Per-event chain; root signature over the head.** `evidence_n.hash = SHA-256(canonical(evidence_n))`; `chain_n = SHA-256(chain_{n-1} ++ evidence_n.hash)`; `root_signature = Ed25519_sign(forensic_key, chain_N)`.
- **Trigger = on-demand snapshot, NOT on incident close** (documented blueprint deviation — there is no closure lifecycle: `status` exists but has no embarked transition, and there is no `closed_at`).
- **Dedicated Ed25519 key in `services/api`, NEVER the ingest CA** (ADR-0016 §5 / §Compliance line 103; the ADR-0014 human↔agent boundary). Key-at-rest mirrors the `ca.ts` pgcrypto pattern.
- **Threat boundary:** tamper-evidence is *relative to the event store at snapshot time, under a no-rewrite assumption* (an RMT re-ingest of the same `event_id` with a later `arrived_at` changes the hash by mechanics, not malice; strong write-once immutability is out of scope).

**Gate A+B (`5478670`) — the pure chain, no signing:**
