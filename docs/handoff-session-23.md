## Procedural notes — Session 23

- **`@react-pdf/renderer` in a Fastify (non-React) service — the novel risk, verified.** Used via `React.createElement` (NO JSX → `tsconfig` untouched), confined to `forensic/report.ts`, consumed only through `renderToBuffer`. It renders cleanly in **Node 24 local AND the Linux CI runner** (yoga = WASM, fontkit = pure JS, Helvetica = built-in standard font — no font files, no Chromium, no native binaries). `@types/react` was added (devDep) as a **reactive correction**: `import { createElement } from "react"` does not typecheck without React's types (react ships none). A second reactive fix: dropping the `: ReactElement` return annotation on the document builder so `renderToBuffer` receives `ReactElement<DocumentProps>` (not `unknown`).
- **PDF determinism — assert content, never bytes.** `@react-pdf` embeds non-deterministic metadata, so the ACs extract text with `unpdf` and assert substance (whitespace-normalised for phrases; whitespace-stripped to recover the long seal tokens across line reflow). No production PDF-parsing dependency is introduced — the api **builds** PDFs, never parses them at runtime.
- **First non-JSON Content-Type in the api.** `reply.type("application/pdf").send(buffer)` works with no config change — `app.ts` sets no `setSerializerCompiler` / `addContentTypeParser`; Fastify sends a Buffer as-is. The existing JSON routes are unaffected (regression suite green).
- **Risk-aligned grain split (proposed, Manuel chose).** Gate 1 = module + content ACs (isolates the `@react-pdf`-renders question); Gate 2 = the thin route + transport AC. The coupling is modest (one module + a ~25-line mirror route), so one gate was defensible; the split de-risked the novel render before wiring — the project's A+B/C rhythm at a smaller scale.
- **`markdownlint` local-vs-CI version skew (carried, confirmed again).** Local `markdownlint v0.40.0` flags `MD060/table-column-style` on pre-existing tables in `SPEC-004`/`SPEC-005`/the `docs/specs/README.md` catalog separator that the CI action (`markdownlint-cli2-action@v16`) does not (main is green). When the local linter reports errors only on lines you did not touch, verify against `HEAD` before "fixing".
- **`gh` CLI is not installed in the agent environment.** CI monitoring used the REST API fallback (token via `git credential fill`, never logged) per CLAUDE.md §CI monitoring fallback; a `node` JSON parser (stdin, not `node -e` type-stripping) extracted per-workflow status.
